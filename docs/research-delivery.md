# Research delivery ledger

Mac is the qualification platform. Portable computation and data contracts must remain independent of macOS; Linux and Windows qualification follows useful local evidence. Each cycle chooses an outcome, freezes its proof, investigates, implements alternatives, compares, integrates or rejects, and records its next resolving action.

## Branch lineage

`program/ksp-macos-research` starts from freshly fetched remote main. Preserve existing branches and worktrees. Complete the laboratory checkpoint here; branch managed source reconstruction, modern Unity, DOTS, and performance alternatives from its qualified commit. Stack actual dependencies and keep independent alternatives as siblings. Maintain one integrated playable candidate; promote complete reviewed outcomes incrementally. Branch existence alone is not qualification.

## Capability gates

| Capability | Acceptance | Next resolving work |
| --- | --- | --- |
| Trustworthy laboratory | Bound workloads; complete live receipts; compatible repeated comparison; exact restoration | Bind craft/checkpoint family, simulation-time flight observer, graphics readback, overhead measurement and paired inference. |
| Controlled reconstruction | Unchanged rebuild, launch, deliberate effect and rollback | Establish assembly-level IL recomposition first; separately compile generated C# against original references and resolve failures. Reflection, serialization and mod interfaces require their own tests. |
| Faster playable KSP | 1080p targets through 256 parts; mission, save/reload and one-hour play | Screen all 30 cells, attribute costs and select the first measured target. Qualify Retina afterward; measure 512 as capacity frontier. |
| Modern native KSP | Private playable pinned modern Unity/ARM64/Metal, selected DLC and MechJeb | Recover matching-2019 project: assets/shaders -> scene -> menu/editor -> flight -> staging/save/load -> DLC/MechJeb -> mission. Resolve editor availability, asset bindings and native dependencies. |
| Interchangeable subsystem | Explicit state ownership, verified behavior and whole-workload cost | Select a measured boundary; test original/replacement, stale results, cancellation, topology and restoration. |

Stretch work includes higher physics warp, broader mods, ECS/DOTS, different physics/rendering and an alternative runtime. Freeze supported behavior and completion tests before each experiment. A negative finding can close a research question; it cannot close an unmet playable capability.

## Active lanes and experiment record

Keep one performance and one reconstruction experiment active by default. A shared prerequisite or decisive finding can change the order. Record hypothesis, target capability, frozen inputs, competing routes, acceptance tests, evidence, remaining unknowns and next resolving action. Include capture, packing, transfer, synchronization and publication in complete-workload cost.

The first performance target after a verified dev loop is startup/initial loading: its savings compound across every subsequent experiment. Freeze installed content, settings and mod initialization; distinguish first use from warm filesystem/shader caches. Measure owned process launch to the observed main-menu Start boundary separately from interactive menu readiness and checkpoint-to-flight readiness. Avoid deleting shared caches. Attribute assembly/mod scanning, config/part loading, assets/shaders and engine initialization before choosing a fix. Run timed startup confirmation without competing builds; reconstruction smoke timings with background work cannot establish a startup speedup.

The next delivery path is progressive mod qualification and recovery. An outer supervisor owns dependency-complete rings, fresh disposable instances, CKAN transactions and crash receipts. Start from a verified minimal ring, add groups, and minimize reproduced failures while retaining the working fallback. Conflicting mods can form a minimal failing group; do not invent a single culprit. Invalid/unstable trials remain inconclusive. Recovery starts a fresh owned process at the last verified ring. In-process assembly unloading, Unity/native fault containment and progressive hot loading require separate proofs.

The initial recovery state machine plans dependency-safe trials and rejects stale results/catalog changes. It does not yet execute CKAN operations, authenticate crash receipts or recover a live game. Bind those adapters before claiming self-healing. Later import/optimization/translation tooling must use the same frozen mod inputs, interfaces and behavior gates.

Use a small supervisor outside KSP with immutable launch profiles and a last-known-good checkpoint. Profiles freeze engine, architecture, assets, packages, replacements, settings and permitted saves. The supervisor journals prepare, launch, startup handshake, checkpoint loading, workload, qualification and recovery. Rings describe achieved capability, rather than dictating a fixed nesting of installations. Diagnose the same failure signature at the same loading/workload stage; preserve uncertainty for flaky or unrelated failures. Reduced-mod diagnosis uses copied saves and cannot overwrite a save containing missing mod parts. Import/optimization/translation creates candidate artifacts outside the game and qualifies them before promotion. Modern Unity and alternative runtimes use the same supervisor contract.

Candidate routes include settings/scheduling/allocations and existing mod fixes; managed plugins/IL/rebuilt assemblies; Rust kernels or persistent native subsystems; asset/shader recovery and Unity migration; contiguous C#, Jobs/Burst, Entities and alternative solvers; separately hosted or rebuilt runtime. Rank measured benefit, resolving power, implementation effort and integration cost. Compare OO C#, contiguous C#, Jobs/Burst, Entities and Rust on the same representative workload, initially retaining rendering and physics ownership. Test Entities Graphics and solver changes independently.

Freeze numerical tolerances before implementation. Validate loading, resource and force ownership, staging, docking, scene/topology changes, stale work, cancellation, save/reload and restoration. Use independent analytic checks or invariants. Confirm candidate gains with six alternating pairs; promotion normally requires >=5% gain and a positive paired confidence interval. Confirm >3% mean-cost or >5% tail regressions before accepting; inconclusive evidence stays inconclusive. Current single-pair tooling cannot make that decision.

## Infrastructure obligations

Continuum owns the C#/Rust laboratory, integration adapters, comparisons and packaging. Reuse Actions portable/private checks; introduce desktop Unity builds separately from Android when an actual project exists. Ops owns admitted Forge sessions, editor/runtime installation and private storage. Stack records verified build/install paths after they exist. Inspect current repository state before extending these owners; do not duplicate their tooling or claim capabilities from planned configurations.

Use Meko clone/record operations and CKAN. Keep reference and playable installations intact, separate writable saves and transactional changes in disposable copies. Reserve visible Forge sessions; run one timed workload without competing builds and control only owned processes. Startup, headless throughput and visible flight remain distinct measurements.

Keep proprietary source/assets/saves/distributions and detailed receipts in private laboratory storage. Preserve provenance. Potential community artifacts include original plugins, diagnostics, owner-installation migration tools, replacement components, documentation and upstream fixes. The owner makes the publication decision for the exact artifact. Gimbal receives findings with workload, fidelity and applicability limits.
