# Research delivery ledger

Mac is the qualification platform. Portable computation and data contracts must remain independent of macOS; Linux and Windows qualification follows useful local evidence. Each cycle chooses an outcome, freezes its proof, investigates, implements alternatives, compares, integrates or rejects, and records its next resolving action.

## Branch lineage

`program/ksp-macos-research` starts from freshly fetched remote main. Preserve existing branches and worktrees. Complete the laboratory checkpoint here; branch managed source reconstruction, modern Unity, DOTS, and performance alternatives from its qualified commit. Stack actual dependencies and keep independent alternatives as siblings. Maintain one integrated playable candidate; promote complete reviewed outcomes incrementally. Branch existence alone is not qualification.

## Capability gates

| Capability | Acceptance | Next resolving work |
| --- | --- | --- |
| Trustworthy laboratory | Bound workloads; complete live receipts; compatible repeated comparison; exact restoration | Bind craft/checkpoint family, simulation-time flight observer, graphics readback, overhead measurement and paired inference. |
| Controlled reconstruction | Unchanged rebuild, launch, deliberate effect and rollback | Establish assembly-level IL recomposition first; separately compile generated C# against original references and resolve failures. Reflection, serialization and mod interfaces require their own tests. |
| Faster playable KSP | 1080p targets through 256 parts; mission, save/reload and one-hour play | Screen all 30 cells, attribute costs and select the first measured target. Qualify Retina afterward; measure 512 as capacity frontier. |
| Modern native KSP | Private playable pinned modern Unity/ARM64/Metal, selected DLC and MechJeb | Recover matching-2019 project: assets/shaders -> scene -> menu/editor -> flight -> staging/save/load -> DLC/MechJeb -> mission. Resolve editor availability, asset bindings and native dependencies. |
| Interchangeable subsystem | Explicit state ownership, verified behavior and whole-workload cost | Select a measured boundary; test original/replacement, stale results, cancellation, topology and restoration. |

Stretch work includes higher physics warp, broader mods, ECS/DOTS, different physics/rendering and an alternative runtime. Freeze supported behavior and completion tests before each experiment. A negative finding can close a research question; it cannot close an unmet playable capability.

## Active lanes and experiment record

Batch independent changes toward a complete outcome and implement them concurrently. Resolve actual dependencies in order, then exercise one integrated candidate. Isolate pieces only when a failure or consequential ambiguity needs attribution. Record the inputs, evidence and remaining unknowns needed to resume the work; avoid a separate ceremony for every small optimization. Include capture, packing, transfer, synchronization and publication in complete-workload cost.

The first performance target after a verified dev loop is startup/initial loading: its savings compound across every subsequent experiment. Freeze installed content, settings and mod initialization; distinguish first use from warm filesystem/shader caches. Measure owned process launch to the observed main-menu Start boundary separately from interactive menu readiness and checkpoint-to-flight readiness. Avoid deleting shared caches. Attribute assembly/mod scanning, config/part loading, assets/shaders and engine initialization before choosing a fix. Run timed startup confirmation without competing builds; reconstruction smoke timings with background work cannot establish a startup speedup.

Optimize the loading architecture in this order: eliminate repeated preparation, reduce the work required for the requested capability, then overlap independent work. Separate preparation (content-addressed indices and runtime-ready artifacts), residency (streaming, retention and prefetch) and execution (explicit readiness and state publication). Track menu, editor and selected-flight readiness independently; deferred cost remains part of the complete workload. Start with one preparation/cache service and a bounded dependency scheduler rather than a general runtime rewrite.

The intended replacement is a prepared game image with demand-driven resource readiness. A complete cheap catalog exposes names, definitions, config results, dependencies and construction recipes before heavy Unity objects exist. Stable versioned handles identify resources across loading, eviction and reload; futures represent individual waits. A bounded scheduler deduplicates requests and prioritizes their dependency closure. Preparation survives game restarts in the native companion. Pack indexed chunks by expected use and lifetime; share mapped artifact pages before introducing transient shared-memory transport. Unity publishes complete current results on its owning thread. Resolve the active flight working set before its hot loop rather than issuing per-part futures each frame.

Target a usable shell followed by action-specific readiness, with loading screens optional. Consumers that require synchronous constructed objects need explicit adaptation or capability-gated activation. Distinguish complete metadata from object residency when examining mod assumptions; retain eager profiles for unresolved consumers. A faster menu that shifts cost to editor or flight is a changed readiness contract and must report those costs. Implement one real consumer path first, then replace the largest remaining avoidable cost.

An ARM64 Rust worker outside the Intel player is an authorized research route. Begin with batched local control messages and immutable artifact files for bulk startup results. Use bounded shared buffers only where measured repeated transfer warrants them. Keep Unity state publication on its owning thread; each job carries an identity, input/scene generation, recipe identity and cancellation state. A worker owns its computation and buffers; the bridge applies only complete current results. Compare total capture, conversion, transfer, queueing, computation, waiting and publication against in-process x86 Rust and managed alternatives. Async scheduling alone cannot establish a speedup or remove work performed in Unity's native loader. The Intel player cannot load ARM64 code in-process; a modern ARM64 player is a separate program path.

The next delivery path is progressive mod qualification and recovery. An outer supervisor owns dependency-complete rings, fresh disposable instances, CKAN transactions and crash receipts. Start from a verified minimal ring, add groups, and minimize reproduced failures while retaining the working fallback. Conflicting mods can form a minimal failing group; do not invent a single culprit. Invalid/unstable trials remain inconclusive. Recovery starts a fresh owned process at the last verified ring. In-process assembly unloading, Unity/native fault containment and progressive hot loading require separate proofs.

The initial recovery state machine plans dependency-safe trials and rejects stale results/catalog changes. It does not yet execute CKAN operations, authenticate crash receipts or recover a live game. Bind those adapters before claiming self-healing. Later import/optimization/translation tooling must use the same frozen mod inputs, interfaces and behavior gates.

Use a small supervisor outside KSP with immutable launch profiles and a last-known-good checkpoint. Profiles freeze engine, architecture, assets, packages, replacements, settings and permitted saves. The supervisor journals prepare, launch, startup handshake, checkpoint loading, workload, qualification and recovery. Rings describe achieved capability, rather than dictating a fixed nesting of installations. Diagnose the same failure signature at the same loading/workload stage; preserve uncertainty for flaky or unrelated failures. Reduced-mod diagnosis uses copied saves and cannot overwrite a save containing missing mod parts. Import/optimization/translation creates candidate artifacts outside the game and qualifies them before promotion. Modern Unity and alternative runtimes use the same supervisor contract.

Candidate routes include settings/scheduling/allocations and existing mod fixes; managed plugins/IL/rebuilt assemblies; Rust kernels or persistent native subsystems; asset/shader recovery and Unity migration; contiguous C#, Jobs/Burst, Entities and alternative solvers; separately hosted or rebuilt runtime. Rank measured benefit, resolving power, implementation effort and integration cost. Compare OO C#, contiguous C#, Jobs/Burst, Entities and Rust on the same representative workload, initially retaining rendering and physics ownership. Test Entities Graphics and solver changes independently.

Freeze numerical tolerances before implementation. Validate loading, resource and force ownership, staging, docking, scene/topology changes, stale work, cancellation, save/reload and restoration. Use independent analytic checks or invariants. Start with two comparable measurements; when they agree enough to choose the next action, move on. Add repetitions only when variability or a specific qualification decision needs them. There is no mandatory six-pair confirmation batch. Keep startup-boundary evidence separate from playable behavior, and preserve inconclusive results when measurements cannot resolve the decision.

## Texture loading experiment

Keep request preparation separate from the stock serial texture conversion and publication owner. PNG/JPEG request prefetch must have a bounded window and memory reservation, avoid duplicate sends, drain already-completed waits, and abort/dispose its unconsumed work on cancellation. Preserve normal-map, flag mipmap, icon readability, compression and registration behavior. A completed request is not a completed texture.

The independent DDS alternative retains stock header parsing, format selection and publication while replacing whole-file and payload arrays with a file-backed mapped upload. The mapping must remain alive through synchronous Unity upload and be released on every completion or exception. Restrict this experiment to an immutable disposable profile; concurrent truncation of mapped files is outside that contract. Retain a managed fallback when mapping is unavailable.

Compare the same prepared catalog and DLC profile with each alternative separately. Include admission in launch cost, ordered texture metadata and load/error sequence, scoped loading costs, bounded ownership counters and cleanup. Metadata parity establishes the startup seam only; it does not qualify rendered pixels or gameplay. One baseline and one candidate can settle a clear result. Repeat only for a specific ambiguity.

## Replacement boot system

Use [replacement architecture](research-replacement-architecture.md) for the current measured boundaries and coherent asset, vessel-rendering and computation paths. Remove avoidable work and persistent graph overhead before translating individual functions.

The target is a prepared game image and capability-driven resource realization. Cook durable runtime-ready data once; open its catalog directly, construct the requested working set, and publish through explicit compatibility boundaries. Extend texture payloads toward model/material recipes, part definitions/prefabs and scene state rather than optimizing every old loader independently. Mod consumers that require eager objects need a compatibility adapter. Direct public texture fields make lazy realization a consumer-rewrite problem, not merely a dictionary lookup change.

The first image prototype captures final raw texture bytes and format/mip/readability/color/profile metadata during an original cook. Reuse bypasses file parsing, decoding, conversion and compression. Unsupported rows use original loaders. A structured startup dispatcher completes ready child work inline, preserves genuine waits and budget yields, and retains ordered registry publication.

Separate producer provenance from consumer identity: retain the exact producer helper snapshot with the image and bind the other input DLLs. Consumer-only changes can use the same supported artifact contract. Changes to cooking semantics, resource-producing helper behavior or artifact interpretation require a new recipe epoch or cook. The asset catalog similarly permits reviewed changes to its resource-free helper consumer while retaining source inputs, runtime recipe/blacklist and compiled-graph checks. These are explicit roles within the private immutable profile, not a general exemption for arbitrary mod changes.

Native admission streams both original digests together, hashes independent files concurrently, avoids redundant prelaunch full reads, and retains full post-run checks. Its standalone operation measures admission without launching the game. Prepared-image reuse uses cheap source/payload metadata guards under reserved immutable ownership; hashes established during cooking remain provenance. This prototype does not claim hostile-writer protection.

Texture capture recipe `stock-raw-mips-png-normal-readability-restored/v2` includes final stock-generated PNG normal-map mip chains. During private preparation only, the pinned PNG/RGBA32 conversion temporarily retains readable pixels through stock mip generation, captures final bytes, and restores unreadability through recursion-safe cleanup. Cleanup failure invalidates preparation. Earlier images remain preserved but do not satisfy this new recipe; prepare a fresh directory. Metadata/payload checks do not establish source-channel decoding, GPU sampling or gameplay fidelity.

Active startup components share one process-local pinned game identity result. The first hash is bracketed by file/marker metadata checks; guarded reuse requires the same loaded assembly/module, MVID, canonical private path, run and refreshed length/mtime. A discrepancy permanently rejects that admission. Producer/mod fingerprints and hook ownership checks retain their distinct inputs. The existing native DLC proof does not authenticate managed inputs, and reserved immutable ownership remains a precondition.

The existing `--startup-world-timing true` laboratory option also installs eleven bounded model/part scopes. Inclusive times overlap; exclusive times subtract only instrumented children. MU parsing and Unity publication remain mixed. Reports retain calls, first/max durations, errors, foreign-thread omissions and stack integrity; zero coverage is not zero cost. Use the next already-needed boot to rank work, without multiplying timing launches.

Deferred terrain remains opt-in with `--startup-deferred-terrain true`. It retains analytic static site registration and records a pending stock geometry/placement obligation, fulfilled by actual site consumers once per shared sphere. Mobile, water, raycast, randomized and unsupported sites use original work. `--startup-site-proof Desert_Airfield` captures actual getters, coordinate publication, repeat reads and radial invariants. Completion does not establish parity with an independent stock reference. The first completed native fulfillment failed frozen spawn-position parity and is not qualified for ordinary use.

## Infrastructure obligations

### Visible flight diagnosis

The laboratory `run` command accepts `--flight-save` and `--flight-checkpoint` to load an immutable checkpoint in the disposable instance. `--flight-seconds 10` captures simulation time after `--flight-settle-seconds 2`; a separate wall timeout and frame cap retain incomplete results as invalid. Use `--flight-max-delta 0.02`, `0.04`, or `0.08` to vary the catch-up allowance. Record the effective integration step separately: this limit is a scheduling treatment, and physics warp changes the integration step. `--flight-warp 4` requests LOW physics warp; `--flight-atmosphere true` supports the normal-time atmospheric checkpoint. The initial runner rejects the combined atmospheric 4x case until that path is qualified.

Diagnostic flights disable VSync and the frame cap in memory, record effective graphics and camera state, and restore owned settings. Optional resolution, AA and shadow changes are declared treatments. Capture now replaces the stock camera update with a physical-root-relative view at 50 metres and 60-degree field of view. Native pre-cull observations must retain the declared pose within 5 mm and 0.005 degrees. The flow-axis effect camera keeps its stock orientation. This camera contract requires a new matched reference; older seeded-camera captures are exploratory evidence. Diagnostic cleanup restores the seeded laboratory view before the owned process exits.

The one-time material census records shader declarations, material values, textures, enabled passes and known per-part heating/highlight inputs before capture. Material clone identity does not establish different rendering semantics. Arbitrary property-block overrides cannot be enumerated in this engine; those sources remain excluded from exact material groups until a supported replacement shader contract exists. No per-frame property hashing is introduced.

For ordinary private laboratory play, use `--continuum-flight-aero-live` and an absolute `--continuum-flight-live-output=...` directory. The in-game toggle or F8 restores stock effects or enables experimental batching. This adapter excludes timed capture ownership, releases synchronously on scene/vessel/staging/docking/part changes, and reconstructs after a stable interval and native destruction gap. Three bounded attempts per state epoch prevent repeated preparation failures from producing an endless hitch loop. Each attempt has separate lifecycle evidence and a transition journal including construction cost. Stock fallback and lifecycle recovery do not establish shader or image equivalence.

`--flight-entry-target-altitude 10000` derives a descending Kerbin orbit in memory from the selected orbital checkpoint. The recipe begins at 90 km with a 134.5 km apoapsis and -20 km periapsis; it retains the original vessel, parts, modules and control state. Epoch-dependent inertial/body-frame coordinates and descending radius/velocity are checked before mutation. Stock orbital warp above the atmosphere and bounded physics warp during approach stop before normal-time capture. Admission records its actual altitude rather than promising an exact-altitude hold. Approach has its own 180-second wall deadline and phase/thermal/density/pressure observations. Original part identities must survive admission; breakup, lost context, timeout and incomplete capture remain explicit invalid evidence, never a silently smaller craft benchmark. Owned warp is restored on every exit. The runner retains entry evidence even when no capture began.

`--flight-no-aero-fx true` suppresses the stock reentry visual cameras through the original aero settings consumers, while retaining physical heating and aerodynamics. `--flight-aero-quality 1` retains the shipped lower-quality effect; it changes both the replacement shader level and occlusion-map resolution. These mutually exclusive rendering treatments require matching quality readbacks at capture start and end. Full suppression also requires effect/depth cameras disabled at both boundaries. They do not establish visual equivalence or an invariant state on every intervening frame. Keep the effect cameras' repeated vessel submission separate from physics cost when choosing a replacement boundary.

`--flight-aero-batch true` is an experimental replacement for opaque vessel geometry submitted to the three stock reentry cameras. Prepare root-space mesh packets with one rigid transform bone per source; retain original shaders, cameras, physical parts and main-view renderers. Bound packet size and bones; retain stock rendering for alpha, existing skinned geometry, deforming compound parts such as struts, mirrored transforms and unsupported layouts. Track actual source and proxy-frame ancestry, including detached physical-part hierarchies. Temporarily switch only owned rendering suppression during each effects-camera callback, restoring originals afterward. Topology, context, visibility, authored scale or lease faults restore stock rendering and invalidate candidate acceptance. Full-frame cost includes native skinning, bounds updates and camera leases; report preparation separately. The runner requires a bound complete lifecycle sidecar, zero faults, positive coverage and all three camera roles exercised. Initial transform checks do not prove native moving-pose or image equivalence. Per-source shader inputs and object-space behavior remain explicit fidelity gates.

`--flight-part-batch true` with an absolute `--flight-part-shader-bundle` enables supported main-view instancing. The runner hashes the bundle and binds a positive native draw/cleanup report. Supported stock specular/mapped-emissive families retain explicit texture, thermal, rim, opacity and probe inputs; other sources stay on the original path. The opt-in `--flight-part-standard-fallback true` declares a diagnostic shader alternative. Native drawing and restored source ownership are proven for one frozen atmospheric case; shader appearance, shadows, arbitrary property blocks and ordinary-play lifecycle remain unqualified.

`--flight-part-retained true` requires both part and aero providers. It retires FX-covered original MeshRenderers throughout the run while preserving total main batching coverage; sources outside owned FX coverage keep their camera leases. Rigid sources use shared physical-part poses and frozen child transforms. Animation/Animator ancestry uses one live source pose per frame, with owned AlwaysAnimate culling leases restored on faults and cleanup. Original components remain for stock property-block writers. Reports distinguish rigid/dynamic populations, publication and exact renderer/animation restoration. The runner requires explicit typed counters, publication for every populated pose class and the frozen 5 mm initial recovered-geometry witness. Changed rigid child transforms, in-place mesh mutation and unknown idempotent renderer-disable writers remain outside the contract. Material/property-block checks, probe interpolation and native FX bone transforms remain; this is a bounded ownership replacement rather than complete renderer-graph retirement. Current native evidence shows correct ownership but no useful complete-workload gain, so it stays experimental.

`--flight-gpu-timing-library /absolute/path/libcontinuum_render_timing.dylib` enables an intrusive asynchronous OpenGL diagnostic. The runner binds the library hash before/after the flight and selects timestamp samples using captured frame witnesses. All observed forward flight/FX cameras must have valid aligned spans and render-thread cleanup before GPU evidence qualifies. Camera spans can overlap and exclude work before opaque rendering; do not sum them into full-frame GPU time. Driver rejection, missing events, delayed/dropped readback and incomplete cleanup remain explicit outcomes. Pair this with native thread sampling to investigate submission versus GPU costs. The standalone `thread-sample` binary classifies exclusive call-tree sample occurrences without double-counting children; these are sampled stacks, not exclusive CPU milliseconds.

The shader build helper admits the pinned matching Unity editor, cooks explicit OpenGL or Metal bundles, preserves source/include/tool provenance and verifies actual compiler errors after bundle construction. StrictMode alone did not reject an invalid shader in the recovered editor. A working OpenGL shader bundle in the original game establishes the shader dev loop, not a migrated Metal or ARM64 player.

`--flight-screenshot true` captures one PNG after the timed window closes and before replacement cleanup. Its nonce, process, dimensions and timestamp metadata are retained with the image hash; readback and encoding are excluded from timed measurements. Compare the complete-workload timings and inspect matched stock/candidate views for geometry, motion, occlusion and effect changes before promoting a renderer replacement. A single still image is a visual pilot, not sustained motion or gameplay qualification.

`--flight-perturbation quiet` and `off-center-pulse` use identical cached motion observations at a 0.1 simulated-second cadence. The pulse targets the physical body farthest from the root, breaking ties by flightID. It applies a root-local perpendicular force for 0.25 simulated seconds beginning at one second, with impulse scaled to a nominal isolated-body velocity change of 0.25 m/s. Boundary clipping accounts for the full requested impulse across fixed steps. The receipt binds target, mass, direction, timing, submitted impulse and angular impulse. This is a controlled excitation; constraint response determines the actual velocity. Awake-body counts and parent-local attachment pose changes distinguish existing motion from additional rotation or flex, without claiming joint stress or gameplay equivalence.

`--flight-hide-vessel true` temporarily suppresses active-vessel renderer submissions, leaving colliders and physics components active, then restores those renderer enables. Nonzero matching start/end hidden counts are required. This destructive visual treatment diagnoses the rendering lane; it is not a playable optimization and boundary checks do not prove absence on every intervening frame.

The run receipt retains checkpoint/settings/plugin hashes, owned PID/run identity, capture signals, raw frame and PlayerLoop observations, control readbacks and complete/invalid/interrupted outcomes. PlayerLoop intervals carry monotonic start/end timestamps; summaries include only invocations wholly enclosed in the capture window and report excluded straddlers. Fixed, PreLateUpdate and PostLateUpdate parents contain their children. Summaries use enclosing parents once and retain legacy child accounting when an older capture lacks its parent. Do not add inclusive children or parallel thread samples into a full-frame total. Rendering brackets include CPU work and waits, not exclusive GPU execution. One pre-capture renderer census records mesh/material identity, readability, property blocks, renderer state and FX camera inputs; estimated submissions are not observed draw calls.

`--flight-native-sample true` attaches the system sampler to the owned process; `--flight-callback-attribution true` uses the existing managed callback profiler. Both are intrusive diagnostics and cannot be compared cleanly with uninstrumented runs. Capture-boundary CPU/RSS readings from the native sample receipt are raw process observations, not window-exclusive CPU consumption. Use these variants to identify a subsystem, then remove the profiler before comparing a replacement. Two sufficiently consistent observations settle a direction; extra launches must resolve a specific remaining ambiguity.

Native scene assets are another replacement boundary. The private Unity 2019.4 texture index records stable object IDs, authored mip layouts, color space and stream ranges. A streamed BC7-to-RGBA32 derivative preserves all original container bytes outside four scalar fields per texture and appends prepared mip payloads while retaining the original stream prefix. Inline textures remain explicit original-format cases. Fewer conversion warnings do not establish a faster startup; compare the complete launch and memory cost.

Native asset installation verifies both source and derivative identities, keeps full rollback copies, binds referenced scene dependencies and their payload streams, and blocks laboratory launches during incomplete transactions. Its installed checkpoint requires an explicit native treatment receipt. Fully verify content once at installation; reserve immutable files and guard exact length/mtime plus receipt identities at launch. Restoration performs full post-run content verification and verifies the restored originals. Decoder/layout checks and successful scene activation remain separate from independent decoded-pixel and gameplay proofs.

Continuum owns the C#/Rust laboratory, integration adapters, comparisons and packaging. Reuse Actions portable/private checks; introduce desktop Unity builds separately from Android when an actual project exists. Ops owns admitted Forge sessions, editor/runtime installation and private storage. Stack records verified build/install paths after they exist. Inspect current repository state before extending these owners; do not duplicate their tooling or claim capabilities from planned configurations.

Use Meko clone/record operations and CKAN. Keep reference and playable installations intact, separate writable saves and transactional changes in disposable copies. Reserve visible Forge sessions; run one timed workload without competing builds and control only owned processes. Startup, headless throughput and visible flight remain distinct measurements.

Keep proprietary source/assets/saves/distributions and detailed receipts in private laboratory storage. Preserve provenance. Potential community artifacts include original plugins, diagnostics, owner-installation migration tools, replacement components, documentation and upstream fixes. The owner makes the publication decision for the exact artifact. Gimbal receives findings with workload, fidelity and applicability limits.
