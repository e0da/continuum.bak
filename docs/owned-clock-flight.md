# Owned clock flight

This opt-in KSP consumer transfers simulation time, motion, resources and acquired thermal/provider state to the portable owned-flight worker. KSP retains its real craft objects, cameras, input and UI. Private native run14 observed keypad acquisition, pause, full owned checkpoint save/restore, short 32x/128x demand and clean autosave handback on the original nine-part ComSat payload. This establishes a bounded installed consumer; complete playable KSP, every operator control, render smoothness and whole-game performance remain unqualified.

## Observed native capability

The acquired fixture contained nine authored parts, four native bodies, four resource rows and 25 actual stock modules. Native14 exercised acquisition, pause, save and restore through the in-game keypad consumer. Its persisted XML shell retained all 25 module rows, and fresh-worker restore retained `.0083509999001398771` seconds of owed simulation time. Native13/14 used the cached explicit XML serializer without `XmlSerializers` assembly-bind noise. The portable shell codec suite passed 25 checks, including default-reader compatibility. Earlier native08 restore also retained debt; failed JSON packets remain preserved.

Native14 observed 127.9057x committed progress during a requested 128x probe and 32.0471x during a requested 32x probe. The latter includes prior debt catchup, so it is progress over the observed wall interval rather than an isolated steady demand rate. The original observed-fixed callback counter remained 7,010 across both probes. The session committed 207.84 simulation seconds with no worker faults, partial native publication or reported native/Transform target discrepancies. A transient presentation gap retains the previous coherent display epoch. These are clock/capacity observations for this small vacuum model, not stock 512-part or GPU/render FPS results.

Original autosave triggered synchronous handback: the worker joined, native flags and velocities were restored, owned hooks were removed and the original Fixed subtree was restored before stock save continued. The pinned thermal handback adapter synchronized `Vessel.lastUT` and settled thermal cadence/cache history across the 207.84-second owned interval. The process then quit with exit code zero. This exercises a real stock lifecycle transition, not only explicit disable.

Native14 used helper SHA-256 `b56752cae0737c898873a0f5fdf6971c7a60c12d5d0aba404787e34aa17c3a84`. Its status, rate, XML/OFCB, handback, lighting and image records remain in the private `owned-clock-01` case. The synthesis is `owned-ksp-clock-v0.1.0.md` in the research corpus; local paths and raw game reports remain outside Git. Earlier refusals, JSON omissions and unsuccessful mouse-input attempts remain evidence rather than successful coverage.

The current operator keys are Ctrl+Alt+Keypad0–5; `--continuum-owned-clock-simple-keys` permits unmodified keypad keys for the lab. They avoid stock function keys. Keypad acquisition/pause/save/restore is qualified; mouse buttons remain unqualified because automated event coordinates did not match the actual window. Stock keyboard warp-tier cycling is also unqualified.

## Supported first domain

The observed first factory admits one loaded active uncrewed fixed-topology Kerbin craft. Every other vessel must be unloaded/proto-only. Native rotating-frame ownership is excluded: `mainBody.inverseRotation` must remain false. The Core session and main publisher both retain the source-bound minimum altitude, above the atmosphere and inverse-rotation threshold for the selected body. This first domain is vacuum; it does not implement terrain, contact, mechanisms, docking, staging or arbitrary mod providers. A source-qualified nonphysical unloaded-vessel position facade can continue; loading/unpacking and physical writers still hand back.

The acquired model includes static chemical engines without stock throttle-response history, acquired RCS, finite wheel reservoirs, fixed nontracking flat solar panels and probe command consumption/readiness. The provider factory retains explicit recipes and source hashes. It does not claim stock fuel-route, curve, skin-temperature, response or exhaust-effect equivalence.

Every installed part module needs an explicit capability row. The implemented roles are `engine-no-response`, `rcs-acquired`, `wheel-acquired`, `fixed-solar`, `probe-command`, `sas-service`, `fixed-antenna`, `idle-transmitter`, `cargo-ui`, `frozen-variant`, `idle-engine-animation`, and `passive-no-callback`. The pinned TripLogger/KerbNet classes can retain their event/save shell state under this rule. Fixed antenna deployment and transmission hand back before original operations. The stock SAS angular-velocity clamp is an unsupported writer and hands back before its original setter; a SAS service-level pass is not an owned SAS controller.

`cargo-ui` admits the exact `ModuleCargoPart` outside attachment, settling and construction. Its original `OnUpdate` performs construction highlighting and returns while construction is inactive; it remains available. Pack/unpack, settling, construction and weld entry methods hand back before the original operation. The original settling coroutine can change prefab mass to 20 or 4 in its supported gravity branches, so it is not treated as an inert callback. `frozen-variant` binds the selected variant/catalog identity, index and mass mode without frame callbacks. Variant setters, drag-cube selection, refresh and both static `ApplyVariant` overloads hand back before changing the captured shape/mass model.

`idle-engine-animation` admits only exact `FXModuleAnimateThrottle` with its actual acquired engine unignited/nonoperational, current/requested/main throttle zero, `affectTime=true`, `animState=0`, and a bound named animation clip at zero speed. The component's static local forest, clip identity and state remain bound. Its fixed callback is suppressed with the entire fixed domain. Ignition and inventory animation operations hand back before original execution; a throttle demand from the real input pass also hands back before submission to the worker. This covers an idle visual shell, not powered animation, imported clip-content fidelity or a new exhaust model.

Solar uses the acquired fixed-panel, inverse-square and spherical-eclipse recipe. It does not reproduce stock raycast self-shadowing or tracking. The frozen source/ephemeris validity is 300 simulation seconds. The timeline owns a matching deadline; reaching it is a declared handback. Reacquisition is a fresh source acquisition, not an assertion that stock execution preserved hidden owned wheel/controller history.

## Scheduling and publication

`OwnedClockKspBridge` replaces the complete admitted Unity `FixedUpdate` node with its own empty node. That removes script fixed callbacks, native fixed physics and delayed fixed callbacks together. It retains the exact original subtree and restores it into the latest PlayerLoop, removing only the owned pre-Update publication callback. Native proxy bodies become kinematic, gravity-free and collision-free. Their identities, hierarchy, sibling indices and scales remain bound.

`OwnedFlightWorker` owns its Host/Session/Timeline and advances independently from rendering. Warp scales requested progress; it does not multiply a Unity physics delta. Local intervals remain governed by the configured mechanical policy, numerical budget and event/provider boundaries. Owed time remains in the timeline. No worker callback reads Unity objects.

Immediately before `ScriptRunBehaviourUpdate`, the service acquires one retained presentation lease. Its descriptor and bank provide the same physical epoch. Publication validates source/region identities, altitude/validity, finite native conversion, resources and thermal limits before starting field writes. It sets committed UT, calls `Planetarium.UpdateCBs` without a second clock increment, publishes body proxy poses/properties, resources/temperatures, vessel statistics and active orbit state, then invokes the selected provider publisher. Setter failures are marked as partial publication; the implementation does not rerun a stock force fold or claim general rollback.

The original active `OrbitDriver` physical tracking and `VesselPrecalculate.MainPhysics` are suppressed while owned. Before native acquisition, original `VesselPrecalculate.Update` settles pending corrections; native14 recorded their flags exactly zero after settlement. Its Update is then suppressed while owned so it cannot reapply those corrections against the committed publication. `CalculatePhysicsStats` supplies the published aggregate facade. `FlightIntegrator.Update` is suppressed because its rendered path also owns occlusion/thermal inputs. The rest of the rendered shell remains active under the selected provider/managed-writer scope.

The scoped stock input pass calls the actual `FlightInputHandler.FixedUpdate`, including `SetControlState` and `FeedInputFeed`, after releasing the presentation lease. This avoids retaining a bank while an original controller may demand synchronous handback. During this compatibility pass, `TimeWarp` exposes a bounded controller delta and normal LOW input mode rather than treating owned demandwarp as stock rails. The result is submitted with `LiveNextCommit`; unavailable command authority submits zero controls. This is live input delivery, not render-partition-invariant replay of every stock controller.

The admitted `ModuleCommand.IsHibernating` facade returns its acquired hibernation field while owned. Increasing requested progress is not stock rails and does not activate the stock automatic rails-hibernation predicate. `HibernateToggle(KSPActionParam)` restores before the original operation. Other GUI/reflection changes to retained hibernation policy fields are detected before the next publication; this does not prove absence of transient arbitrary writes.

Numeric demand and stock warp fields are separate. At numeric 32x/128x, original `CurrentRate`, current and previous rates remain 1, and the stock rate index remains 0. Acquisition requires an initial target rate of 1 with no active autowarp. The original warp UI therefore shows normal; the owned panel displays actual requested demand. Stock keyboard tier controls have no qualified owned interpretation.

Native read facades and guarded writers are transformed at original managed callsites in the pinned stock and MechJeb assemblies. The rewrite preserves operand evaluation and all original operations outside an owned receiver. Selected resource/thermal/force field stores and direct `Planetarium.time` stores are also guarded. An unsupported writer restores the owner before its original operation proceeds. The graph is qualified cold and sealed against the pinned raw Harmony state. Unknown part modules are refused; this is not a universal mutation detector for arbitrary loaded native/managed code or reflection writes.

`CheckLoop` currently runs through the owned pre-Update callback. Removing that callback also removes that detector, while the addon `Update` only refreshes status. An independent removal detector remains an explicit gap; per-frame checks do not prove every callback-removal case is detected. Any future validation lease must retain this distinction and state its detection latency.

## API and integration

The separate request is `CONTINUUM_OWNED_CLOCK_FLIGHT`, whose value is an existing absolute private output directory. The addon starts disabled and excludes the existing live native rigid owner.

Root integration registers `IOwnedClockFlightFactory`. Its `Acquire(Vessel, freshDirectory, runId)` returns `OwnedClockFlightBinding`:

- actual `Native` and `Parts` captures; native/part/context hashes, `ModelScope` and `MinimumAltitudeMeters`;
- exact provider rows `{partId,moduleIndex,sourceType,kind,modelRecipe}`;
- numeric-only `InitializeWorker`, numeric `CaptureCheckpoint`/`RestoreCheckpoint`, and main-only `PublishProviders` callbacks.

The service exposes static `SetEnabled(bool)`, `SetWarp(double)`, `SetPaused(bool)`, `SaveCheckpoint()`, `RestoreCheckpoint()` and `Snapshot()`. Control operations return an error reason or null. `CaptureLightingFacts()` writes same-frame diagnostic facts without changing ownership; protocol 1.4 `clock-lighting` returns their exact saved path in `clock.lightingPath`, or an error with owner status preserved. `ReframeSunward()` is an explicit camera operation and writes its own record without changing worker physics. Existing LiveControl uses the same socket. Clock acquisition/save/restore/disable use a longer bounded transport wait; an unfinished started request reports its request ID as in progress rather than claiming cancellation. A request canceled while still queued cannot execute later.

Pre-admission refusal is retryable only while no authority changed or after verified cleanup with no publication reached. Acquisition stage, error and a fresh attempt receipt remain visible. Native/loop/hook restoration failures remain latched; a refusal is not a completed acquisition.

`OwnedClockFlightService.ReportData` uses schema `continuum-owned-clock-flight/v1`. Nested `EventRow` is a 256-entry overwritten ring, copied only for cold receipt/status export. Each event distinguishes the service's `ownershipEpoch` from the current worker's `numericalEpoch`; restoring a numerical checkpoint does not create a new native ownership lease. The bridge reports `continuum-owned-clock-ksp-bridge/v1`, exact `SourceRow[]` method identities and provider rows. Worker and publication counts are distinct; publication cost is not simulation work or a clean FPS result.

## Checkpoint and handback

An owned checkpoint pauses at an acknowledged worker barrier. Full OFCB preserves the physical bank, mechanical/thermal state, provider history and execution timeline including debt/events. Main-thread `PartModule.Save` captures bounded original module ConfigNodes. Shell persistence uses `.shell.xml` and the established BCL XML serializer with DTDs prohibited, no resolver and byte/character bounds. Before assigning the latest checkpoint, persisted readback must preserve schema/session/vessel, unsigned part IDs, module order/type, the entire ConfigNode text and UT bits exactly. Native08 and native14 observed this gate on the actual 25-module shell and restored retained debt; native14 also exercised keypad save/restore. A private receipt binds both files, hashes, helper, session, ownership epoch, source captures and physical revisions, with `shellEncoding=xml-serializer/v1`. It is not a complete KSP game save.

Unity JSON empirically omitted authoritative custom tables and nested worker/bridge diagnostics in earlier attempts. Diagnostics now use the explicit `ReportJson` encoder; XML replaces only shell persistence. Numeric OFCB is unchanged by that repair. Failed earlier files remain immutable.

Restore accepts only the most recent checkpoint from the same physical/code/source lease. It validates both files and all shell mappings before replacement. It then pauses the current worker and writes a fresh `interrupted-rollback` numeric/shell packet, including current pending demand. That packet does not replace the requested saved target. The old worker is joined while the bridge retains the native and Fixed-loop lease. A fresh numeric-only worker starts paused with zero debt, replaces that initial execution with the saved full checkpoint, loads its shell and publishes one coherent restored epoch. Saved demand is restored intact; offline wall time does not accrue during the replacement. Restore leaves the owner paused for an explicit resume.

If target restoration fails, an immutable failure receipt records the error, worker/bridge state and the target/interrupted paths. When possible it also retains the candidate numeric bank and actual shell separately; a failed partial publication is not presented as a coherent checkpoint pair. The candidate is joined before another worker is created. Recovery restores the retained interrupted execution and shell through a fresh worker, with the original demand intact. If recovery cannot close, the service attempts safe stock restoration; an incomplete cleanup blocks stock transitions. This is an explicit checkpointed recovery path, not rollback of arbitrary native setters. Partial-publication evidence remains latched even after successful recovery.

The report exposes `interruptedCheckpointPath`/`interruptedCheckpointSha256`, `restoreStatus`, `restoreFailurePath`/`restoreFailureSha256` and `restoreRecoveryError`. Checkpoint receipts include `operation` and their own `receiptPath`. Files are created once; target, interrupted and failed-attempt evidence are retained independently.

Before stock save/load, staging, coupling, rails, vessel loading/switching, scene changes or an unsupported clock/frame writer, the service pauses and joins the worker, retains a final numeric/shell checkpoint when possible, publishes final committed state and restores every surviving native proxy before restoring fixed scheduling. Original TimeWarp mode/index/current/previous rates and Unity/Planetarium scales are restored together. Native velocity conversion follows the original OrbitDriver source relationship, including the captured Krakensbane and rotational-frame terms. The first domain excludes inverse rotation; a general inertial/native angular-frame conversion remains outside it.

Original methods are allowed to execute only after synchronous restoration succeeds. Failed cleanup blocks the original transition and remains explicit. Optional checkpoint failure records its error and leaves the prior latest pointer intact; it does not prevent otherwise verified native, loop and hook cleanup. Final diagnostic IO failure is recorded separately and does not undo a successfully persisted checkpoint. An explicit save still rejects a failed persistence gate. No queued stock force is silently admitted at acquisition: nonempty force lists or nonzero source force/torque refuse transfer.

## Cost and remaining qualification

An opt-in paused native08 diagnostic interval measured 26,292 raw certificate checks of 967,680 sealed bytes: 25.6123813 seconds total, about .974 ms per check. Complete publication averaged about .257 ms over 26,296 publications. The scopes overlap and must not be summed or treated as simulation time.

Native09's exact word-block comparison passed the actual loaded-Mono foreign, same-array, absent-method and latched-failure mutation witnesses with its game graph unchanged. Two paused observations measured .249 and .256 ms per check over 973,824 sealed bytes: approximately 74% lower stage cost despite six additional control-reference hooks. Publication remained about .26 ms. No competing build ran in those capture windows. The independent scalar comparison oracle passed 28,380 assertions. This is measured ownership-check work, without a whole-game FPS claim.

Same-frame lighting facts falsified the stale-anchor explanation for the observed dark view: sunlight intensity was .9, no body eclipse was reported, the Sun direction aligned, and scaled-space anchor errors were zero. Camera-to-Sun angle drifted from approximately 157 to 111 degrees; explicit sunlight reframe produced approximately 160 degrees, a 20-degree solar phase view. Craft and planet pixels were inspected. This resolves that observed framing case; it does not establish every lighting condition or high-warp interpolation.

The next qualification remains focused on the real consumer. The
[scale frontier](scale-frontier.md) sets 4,096 authored parts as the first large
stress target, with larger probes through million-part craft and collisions.
Small comparison cases are checkpoints, not the program's capacity ceiling.

1. Qualify actual mouse buttons, stock warp-key handling and broader control-reference transitions. Observed keypad and protocol operations do not establish every ordinary control mode.
2. Qualify smooth presentation interpolation and broader lighting/camera conditions. Render interpolation is an observation projection and must not alter committed physics or hide debt.
3. Extend causal power/readiness, thermal accuracy and analytical coast through interior/tangent eclipse boundaries while scalar and thermal transactions remain active. Frozen-resource rails are not this model.
4. Preserve rejected-step and checkpoint continuation under those extensions, and qualify the exact source-pinned transitions before broader docking/staging, contacts, background providers or mod support is claimed.
5. Close the independent callback-removal detection gap and measure any changed ownership-check path without silently weakening the writer/epoch scope.

The implementation preserves the existing 1e-4 metre and .002 degree native/Transform pose gates. Native14 observed the bounded keypad/clock/continuation capability above; full playable behavior, larger-craft capacity, universal provider equivalence and whole-game FPS remain unqualified.
