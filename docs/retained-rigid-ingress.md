# Retained rigid ingress

`RetainedRigidIngress` is a fixed-topology, single-thread-owned numeric input bank. It replaces rebuilding immutable member lists at every scan. It does not read Unity objects, supply force authority, or qualify a gameplay trajectory.

Construct it once from the admitted member rows and optional stable identities. A row retains its member ID and stable external identity. `BeginScan`, `Set(row, stableId, ...)`, and `CompleteScan` stage a complete observation. Visits may follow any publication order, but each row must appear exactly once with its admitted identity. Removed members, slot reassignment, duplicate visits, nonfinite values, nonpositive mass/inertia, or invalid rotations reject the scan. Recreate the owner for topology changes. `AbortScan` cancels an incomplete observation.

Local position, local rotation, local CoM, and principal inertia frame are relative to the same declared craft frame. Units must remain consistent with the caller's native boundary; KSP ingress uses tonnes, metres, and tonne-metres-squared. Each native body contributes once, including its already-resolved physicsless mass; the ingress does not add part mass again. Stable slots should be native-ID sorted at admission; a depth-ordered Unity scan supplies each body's retained slot rather than its visit index.

Every successful scan returns a readonly `RetainedRigidPropertySnapshot`. Unchanged exact input bits reuse the current generation. Changed inputs update retained centres/axes, then recompute the complete canonical member-ID-ordered two-pass compensated fold and original Jacobi principal-axis model. There is no subtract/add accumulation history. Pending values and the new property snapshot publish together only after all validation succeeds. A rejected scan retains both the prior member values and property generation.

`GetMember(row)` returns a readonly value copy for original-body property publication. `Current` returns a value copy. Successful hot scans, reductions, and these reads allocate no arrays, member objects, or property classes. `ToProperties()` is a deliberately allocating cold adapter to the existing immutable `RigidAssemblyProperties` API; consumers needing no hot allocation must retain the value snapshot directly.

`RetainedRigidPerformanceRing` stores bounded value samples with lifetime totals and a chronological retained tail. `Record` performs no clock read, serialization, or allocation; caller-provided ticks must use `ClockFrequency`. Ingress/property/publication/observer durations may nest: each must fit the enclosing sample, and they must not be summed into exclusive cost. Observer ticks cover only the explicitly supplied observer scope. Frame records can use zero delta; physics records require positive delta. `Snapshot()` allocates a detached array only on demand. The ring is single-owner-thread state, with no synchronization or inference of missing callbacks.

The focused portable test project compares all reducer fields bitwise against the existing batch reducer over changing mass, CoM, and principal frames, checks independent analytic/degenerate tensors and failed-scan atomicity, and checks hot allocation and bounded ring behavior. Source acceptance and these checks do not establish live native property coverage or a performance improvement. Root integration must bind the scan to actual original body readbacks and measure whole ownership cost.
