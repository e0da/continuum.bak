# Adaptive coupled mechanical transactions

`OwnedRuntimeMechanicalPolicy` selects repeated isolated trials rather than a global physical cadence. Defaults retain a `.0001` minimum refinement interval, `.1` maximum, position/velocity differences `1e-4` metres and metres/second, orientation `1e-6` radians, and scaled momentum/resource/provider differences `1e-6`. A positive semantic event/input tail may be shorter than the refinement minimum when both halves advance representable time; it must still satisfy the same estimate. These are frozen local estimates, not a universal global-error certificate.

`Systems.SetMechanicalPolicy(expected,policy)` publishes policy/controller continuation at the same physical time. `Session.AdvanceLocal` selects `Host.AdvanceAdaptive` only when enabled; reference mode remains the original full fold. A trial-safe schedule declares that all future-relevant mutable state lives in the bank and its schedule instance has no unrepresented side effects. Builtin is admitted; unmarked HMR is rejected before installation while adaptive mechanics is active.

The host retains a coarse and a refined World/Systems/Session. Numeric bank reset includes resources, providers, members, input history, deferred thermal forcing and mechanical continuation; retained mass reducer inputs are synchronized. No checkpoint/JSON roundtrip occurs in this path. Trial sessions have separate physical guard scratch. The same held controls run one full interval and two halves. Estimates compare world COM position, COM velocity, quaternion chord angle, angular momentum, resource amounts and provider values. Thermal frontiers/temperature are excluded because current thermal evolution does not feed mechanical force or mass; accepted refined thermal history is retained unchanged.

An accepted refined state publishes once into an unleased live bank, with one input-history interval and one live state revision. Rejected trials never publish. Controller next interval, accepted/rejected counts and trial counts are bank-owned; a completely failed search leaves that live continuation untouched and reports its rejected work separately. Source admission covers topology/configuration/code ownership. Complete observation ticks include limiter calculation, cold cache construction, trial resets, all folds/rejections and publication. Systems counters charge the two accepted physical half-folds; mechanical accepted counts identify the single published interval. No speedup is claimed from this source change.

Trial halves use distinct representable clock endpoints and derive the remaining interval from the first committed trial stamp. An actuator deadline below clock resolution is rounded up only to its earliest representable endpoint, bounded by the caller's semantic endpoint. An adjacent one-ULP endpoint has no interior half-step: it uses one isolated original fold and bounds its entire mechanical/resource/provider change under the unchanged budgets before publication. This explicitly counted roundoff coalescence preserves the prior suggested interval. `roundoffCoalescedIntervals` is checkpointed; observation additionally reports actuator clock ceilings and their last duration. It is not advertised as a two-half estimate. An over-budget adjacent step rejects unchanged.

`FindActuatorBoundary(expected,controls,horizon)` calls the original ordered Actuate/Withdraw fold on a noncommitting retained bank, suppressing diagnostic counters. It finds newly reached exact resource-zero or requested wheel-capacity writes, then uses at most 64 representable bisections. Initial blocked reservoirs/capacity are not new events. Shared pools, mixtures, electrical competition and row priority use original operations. The result is a source/configuration-bound held-control forecast; control/topology/provider changes invalidate it. Adaptive admission caps its interval by the original limiter. The forecast is charged work and can require a full bank copy plus many actuation probes; it is not an assumed free analytic shortcut.

Runtime checkpoint v5 contains the complete mechanical policy/controller state, including the selected numerical method, execution strategy and deadline strategy. Binary v3 introduced timeline/event DTOs; v4 added method/execution selectors; v5 adds deadline selection. Explicit v1–v4 field maps/digests omit fields/types that those producers did not contain; v1 also omits thermal state. Legacy restore initializes only the choices actually absent from that producer. Derived rate plans are rebuilt from authoritative inventory and controls rather than serialized as future physical facts. This does not load a mismatching historical executable schedule.
