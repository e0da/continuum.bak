# Independent owned flight execution

`OwnedFlightWorker` constructs its Core host/session/timeline through an initialization callback on one dedicated thread. The callback receives only acquired portable data and worker-safe code. Rendering neither requests nor executes physical work. In automatic mode the worker accrues monotonic Stopwatch wall demand independently, pumps bounded atomic transactions, retains remaining debt and sleeps between useful work or command wakeups. In deterministic mode only explicit ordered wall-demand commands create progress. This moves the actual owned execution off presentation cadence; the current timeline's numerical quantum remains a separately declared integration policy, not a claim that adaptive or multirate scheduling is already complete.

The queue retains at most 128 ordered requests. Typed configure/control/pause/warp/demand/step commands return acknowledgements. Overflow rejects a new request without changing admitted commands. Cancellation succeeds only while queued and executes no callback; once started, the caller must await its result. A failed physical transaction retains its prior bank and owed time. A same-time declared repair rebinds code/configuration through the existing timeline without deleting historical demand.

Interactive callers use `SetLiveControls`: it replaces only unapplied control values at the committed frontier while preserving requested time, debt, deadlines and other policy boundaries. Its supersession counters are retained in progress. Recorded replay uses `Configure`/`SetControls`, whose historical FIFO remains unchanged. Live keyboard/socket input therefore need not wait behind seconds of old control demand. Context exposes the same synchronous methods for callbacks already executing on the worker; calling Timeline.Configure directly would leave the worker's held-policy cache stale.

`Invoke` callbacks run on the worker. Read-only invocations may acquire checkpoints or predictions but cannot publish state/code/configuration. Cold mutations require pause and zero debt. Same-time mutations require pause and retain debt; they use an explicit event acknowledgement. Timeline mutations permit paused manual debt consumption only when the existing timeline already acknowledged every changed physical stamp. Replacement through `context.Replace` requires cold debt-free admission and creates a new paused timeline. The old host/session must not be accessed afterward.

These callbacks are trusted portable application code, not a security boundary. They must use one existing atomic Core operation or fully stage a replacement before publication. Arbitrary multi-operation callback rollback is not supplied. If a callback throws after it changed a physical/code/configuration stamp, the worker explicitly faults and does not claim rollback. Host/World bind the writer thread; builtin and declared worker-safe example schedules are admitted by the host, while unmarked schedules are rejected. A marker declares a reviewed portability contract; it does not prove arbitrary third-party code thread safety.

Presentation acquires one `OwnedFlightPresentationLease`, containing an exact bank lease and its captured origin, universal time, context, frame, mode and timeline progress. A short publication-gap acquisition returns null; keep the previous rendered image and retry. Rendering releases its lease after reading, without holding a simulation lock while using Unity. One retained external bank still leaves a write bank available in the existing triple-bank owner. Read pressure is reported and retried with debt retained. The descriptor's environment sample is pure; it cannot overwrite Session's physical start-state guard scratch.

Physical topology, resources, pending thermal ledgers, code reload and checkpoint continuation continue to use their existing Core owner APIs. Save/restore must retain all state in those codecs and obey paused debt-free replacement; same-time HMR can keep queued input. Stop rejects new commands, cancels queued requests, lets a started atomic operation close, and joins the thread. Timeout leaves shutdown explicitly pending rather than aborting a writer.

Run the focused source checks with `dotnet run --project tests/KspContinuum.OwnedFlightWorker.Tests/KspContinuum.OwnedFlightWorker.Tests.csproj -c Release`. They exercise real independent wall progress without rendering, exclusive writer rejection, frozen old bank leases, queue overflow/cancellation, actual triple-bank reader pressure and recovery, failure after actual systems computation followed by debt-preserving repair, rebase coherence, read sampling between physical admission and validation, and live-control supersession against the unchanged historical replay policy. Integration and native visual evidence are separate; no KSP callback or Unity API has been moved to this worker.
