# Compiled owned-system dependencies

`OwnedRuntimeExecutionStrategy.Reference` retains the original owned bulk fold. The selectable `Compiled` strategy removes repeated resolution of immutable geometry and routing while retaining original actuator, resource and surface order. It changes neither the integrator nor the authored force/thermal coefficients. No stock KSP equivalence or measured speedup follows from selecting it.

`Systems.SetExecutionStrategy` is a cold configuration change. A candidate plan is constructed before the new configuration revision is published. `CompileExecutionPlan(expected)` prepares a plan at an exact current stamp, useful after a topology or configuration change. The systems owner also rebuilds an invalid plan before execution; allocations are limited to those structural/configuration boundaries. The checkpoint consumer must persist strategy and restore it before restoring the configuration revision. Adaptive trial systems retain the selected strategy.

The immutable plan contains the original ordered actuator/surface rows, body and region slots, region-local application points/axes/normals, source resource densities and ordered eligible fuel routes. Point composition keeps the original part-to-body-to-region expression grouping. Fuel routes exclude only resources whose admitted flow or region ownership makes the original fold skip them. They retain zero-quantity eligible resources and original pool order. Quantities, fractions and withdrawals remain live sequential operations; no cached availability sum or reordered reduction is introduced.

Plan validity binds definition and topology identity plus configuration revision. A topology split/rejoin changes region-local geometry and requires rebuilding. Flow/enable/strategy changes invalidate configuration admission. Resource mass, COM and principal inertia changes do not alter member geometry in the current world model; they remain live inputs. Introducing articulation or another geometry writer requires an explicit geometry revision and invalidation before this plan can support it.

After actual mass publication, the compiled surface pass evaluates angular velocity once per active region from that region's current orientation, world angular momentum and properties. Atmospheric flow angular velocity is still subtracted at every surface's lever. COM-relative lever arms, world rotations, aerodynamic force, lift and heating remain live. The original ordered force/torque additions are unchanged. A zero-density region rejects aerodynamic rows before point/velocity mathematics; thermal radiation/convection scheduling still executes separately. Vacuum is not a claim that all thermal work disappears.

Counters distinguish plan builds, retained geometry rows, compiled actuator/surface rows, disabled actuator rows, vacuum surface rows and actual region-motion contexts. They are work coverage, not CPU milliseconds. Existing complete-cost observation must include cold construction, structural rebuilding, trial preparation, validation and publication.

The acquired source fixture has 512 authored parts, 426 distinct bodies, 64 resource rows and 65 captured actuator modules expanding to 195 authored actuator rows: 6 engines, 156 RCS nozzles and 33 wheel axes. The captured aero recipe builds 498 surfaces, one per enabled positive-area part. These are source facts for that fixture, not a universal part layout.

The dedicated execution-plan checks compare complete published world snapshots bitwise against the reference path across vacuum/atmosphere, powered shared mixtures, electrical wheels, disabled routes, resource flow changes, topology split and re-lock. They also compare delivered force/torque/resource ledgers and assert active-domain/context coverage. The source is frozen before root execution. A changed numerical integration method must be qualified independently; compiled dependency equality cannot certify its arithmetic or error estimator.

## Staged numerical ownership

The separate embedded-method seam begins one scalar transaction through `BeginMechanical`: actuator resource withdrawals, delivered intent, resource-dependent mass publication and wheel terminal momentum are computed once. Delivered local force/torque is retained about the terminal COM. `SampleMechanical` evaluates a caller-supplied stage pose/tensor and stage-clock field into reusable non-gravity force, torque, environment and aerodynamic heat-Watt buffers. It performs no resource, provider, thermal or input-history publication. The stage torque includes the terminal-to-stage COM lever correction.

`CompleteMechanical` publishes terminal motions, provider state, retained actuator Joules plus midpoint aerodynamic Watts times the interval, and one thermal interval. The world rejects scalar-only incomplete publication. After a successful physical commit the driver acknowledges that actual bank; rejected/canceled transactions abort and restore physical delivered counters while retaining measured effort. This interface uses declared local-wrench/midpoint arithmetic, distinct from the reference fold. Its integrator, mass interpolation and estimator require their own numerical proofs. It currently admits actuator/surface/field inputs, not the reference overload's arbitrary external-force array.

Midpoint aerodynamic heat and environmental forcing are a declared source quadrature. The mechanical error estimator does not bound their temporal quadrature error. The thermal solver estimates integration error for the supplied ordered forcing; it cannot certify omitted variation between mechanical observations. Temperature-dependent mechanical feedback remains unsupported.

`SetWorkObservation(bool)` enables coarse timing without changing physical configuration. Scalar timing includes actuator and mass publication; aero timing includes field/gravity and aerodynamic sampling; thermal and region integration have separate brackets. Plan timing covers rebuilding during preparation. These counters are nested inside overall observed work; do not add inclusive complete-cost observations to them or interpret unmeasured setup/copy/commit cost as zero.

## Compact actuator boundary probes

The compiled boundary finder evaluates the same scalar actuator fold and unchanged bounded bisection on retained scratch resources. It pins the source through a read lease and cold admission, borrows immutable provider/geometry/topology/pose/property inputs, and copies only resource quantities for each probe. Force, torque, heat and wheel-vector output work is skipped because it does not affect the scalar boundary result. Provider terminal scalars and ordered resource withdrawal remain evaluated exactly. Borrowed references are cleared before releasing the lease, including failure paths.

Reference strategy retains the original canceled world-step probe. Differential tests compare deadline IEEE bits, reached row/resource/kind and probe counts across shared mixtures, disabled flow, split regions and saturated/reversing wheels. They also compare complete source snapshots before/after searches and reject borrowing during an active transaction. `BoundaryResourceCopies` counts compact array-copy calls; `BoundaryResourceRowsCopied` counts quantities copied. `BoundaryProbes` and optional `BoundaryTicks` charge the whole search. A cold scratch bank allocation remains possible after topology changes; no full world bank/history/thermal copy occurs per compact probe.
