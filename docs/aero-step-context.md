# Shared aerodynamic step context

`CONTINUUM_AERO_STEP_CONTEXT=verify|query|compare` enables a private experiment around the original `FlightIntegrator.Integrate` root. Absent means off. The experiment preserves recursive part order, directional curves, weighted arithmetic and Unity force publication. It replaces nine reached Mach-curve callsites with six lazy role slots, reset for every root. Each slot retains the original first-use evaluation; reuse requires the same wrapper and exact float input bits.

`verify` records two captured roots, compares each reused value bitwise with the original evaluation at that same callsite, and returns the original value. It does not run a second force calculation. This verifies reached values under the admitted ownership lease; it is not a complete stock/candidate performance comparison. `query` returns reused values and records complete context-plus-root costs, including admission, reset, lookup and native publication. First-admitted-root costs are retained outside capture too. Installation and cleanup are separate costs; surrounding FixedUpdate work and complete frames remain separate measurements.

The experiment pins the original assembly, instruction shapes, reachable managed graph and actual lift-provider dispatch once. A reserved frozen patch/managed ownership lease is checked at installation and cleanup. Root guards check exact bound topology, current part/cube/provider owners and six curve aliases without repeated Harmony or reflection scans. Exact stock `Part` and `CompoundPart` are supported through inherited nonvirtual aero accessors; custom subclasses and absent cube owners are unsupported. Changes between roots can be read afresh; concurrent or within-root curve, patch or native mutation remains outside this experiment's scope.

Admission failure runs the original root without reuse. Unexpected in-root input, owner or result disables further reuse and invalidates the experiment. Already-applied native forces cannot be rolled back, so the report does not claim all-or-none recovery. Completion requires original callsite coverage, no mismatches or observer errors, and observed removal of owned hooks.

Reuse counts alone do not establish a speedup. Compare compatible complete flights with the same helper and frozen inputs, varying only the declared environment mode. Parent/child timing rows overlap and must not be summed. A negative or inconclusive complete-flight result keeps the treatment experimental and off in ordinary launches; it does not establish absent local benefit.

`compare` measures the local owner through common instrumentation. It selects each captured root before timing by a fixed index: even control-original, odd query. Both arms retain admission, slot initialization, role/key checks, lookup/counters and complete window bookkeeping. On control hits the original evaluation runs once and its value is returned, without verification comparisons or per-evaluation clocks. Only query hits return cached values. Pre-capture roots use control-original. There is one original force calculation per root. Completion requires both arms, contiguous alternation, balanced counts and complete per-arm evaluation/cleanup witnesses. Adjacent roots have different physical states; a mixed flight's FPS is not a candidate FPS comparison. Retain all adjacent pairs and cold/bookkeeping costs. The control includes wrapper tax and does not measure untouched-stock root cost.

## Selected native result

The 512-part frontlit atmospheric fixture reached all nine sites and six roles. Two original-return roots checked 30,828 reused values against the original evaluation with zero bit mismatches, faults or fallbacks. The original force calculation ran once per root. A separate query flight completed 151 captured roots: six original evaluations per root and 2,327,514 reused values, with all owned hooks removed.

One clean baseline/query pair used the same helper, frozen profile and 21 inputs. Both captured 3.02 simulated seconds at normal time, 1920×1080, uncapped with VSync disabled, and stable topology. Their starting states differed by one physics step. Mean frame cost was 25.524 → 24.936 ms (39.18 → 40.10 FPS); p95 was 36.942 → 29.468 ms and p99 46.964 → 45.678 ms. Managed fixed work was 7.137 → 7.274 ms per step. This short pair does not establish an attributable gain or tail improvement, and lacks an equally instrumented original root control. Local benefit is unresolved; the candidate and numerical proof are retained. No unchanged frame-pair repetition is needed before measuring that boundary or choosing the larger transaction.

Query context plus original root cost averaged 1.695 ms, including 0.016 ms admission, 1.662 ms root execution and prefix/end bookkeeping. Installation took 71.352 ms, cleanup 53.099 ms, and the first uncaptured invocation 7.259 ms. These are candidate scopes, not a clean original-root comparison. Full frames include their overhead. CPU/RSS and GPU execution were not sampled; FinishFrameRendering is not GPU duration. Actual baseline and query images show the craft, atmosphere, UI and live portraits; long booms extend outside the frame.

The actual assembly metadata and opcode/operand rewrites also passed a private standalone ARM64 Mono preflight without booting KSP. It admitted four shapes and nine sites. This fast loop does not execute the rewritten delegates, preserve original branch labels, install native detours or prove force behavior; those require separate live evidence.

The next larger replacement boundary is one root-level drag transaction: capture mutable inputs into reusable rows, fuse direction and six-face reduction, and publish outputs in original order. Existing complete SetDrag and capture contracts provide donors. A managed flat kernel is the first comparator; native execution must earn its capture, transfer and publication costs. Unsupported providers and Unity force ownership remain explicit boundaries.
