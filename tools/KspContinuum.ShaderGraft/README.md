# Private player backend admission

`recompose-player CLASSDATA PLAYER_DATA NEW_ABSOLUTE_OUTPUT` writes a new loose serialized file and `.receipt.json` beside it. It never installs the result. The parent output directory must exist and be outside the input Data directory. All input/output ancestors must be free of symlinks.

This bounded mode accepts only Unity 2019.4.18f1 serialized version 21, exactly one class141 BuildSettings, the original graphics API array `[17]`, and the pinned KSP CoreModule digest. It reads `UnityEngine.Rendering.GraphicsDeviceType` constants directly from that DLL's managed metadata, verifies Metal16/OpenGLCore17, and writes `[16,17]`. Shader compiler-platform IDs are a different enum.

Before publication it rereads the derived file, compares every other object payload/type/path ID/order, restores the edited array in memory to prove exact original BuildSettings bytes, and compares serialized metadata after normalizing object offsets and sizes. Those layout fields and header lengths may change because the edited array grows by four bytes. Dependencies and other metadata must remain exact. The receipt records hashes and proof outcomes without printing build-token values.

For one resolving offline check, run against the original privately owned Data directory and inspect the receipt's preservation gates; rerun against the derived file in a separate disposable Data copy and require rejection because `[16,17]` is not the admitted original `[17]`. This is an unexpected-input check, not another native rendering run.

The result changes serialized admission only. A disposable native launch must establish actual Metal initialization independently; it does not establish stock shader support. A matching-version Metal donor shader can then render a controlled primitive with independently checked pixels, while missing original UI/world/vessel shader closures remain explicit. Preserve original source files and failed runs; never substitute a complete donor `globalgamemanagers` file.
# Private menu reconstruction

`menu-materials CLASSDATA DATA NEW_REPORT` records serialized main-menu scene material, shader and texture references. `recover-menu CLASSDATA DATA NAMES NEW_DIRECTORY` recovers selected shader metadata and original OpenGL programs privately. Same-name shaders in different files retain separate content identities.

`prepare-menu-cook MATCHING_BUILTIN_DIRECTORY TMP_ESSENTIAL_UNITYPACKAGE NEW_PROJECT_DIRECTORY` prepares matching Unity/TMP source and explicitly approximate original background recipes. Add the independently recovered UI recipes to the generated private shader directory. Matching vendor sources, recovered programs, generated private shader sources, donor bundles and rebuilt game containers stay outside Git. The recipe states the lighting, terrain, atmosphere, fog and transparency fidelity limits; this is a visibility candidate, not stock visual equivalence.

Cook the private source with the existing pinned `BuildShaderBundle.Build` entry point, graphics API `Metal`, no instancing requirement. `graft-menu CLASSDATA TARGET DONOR NEW_OUTPUT NAMES` writes only selected shader objects in a new loose serialized container. It retains path IDs, object order, all unrelated payloads and serialized external metadata, remaps donor shader-only references to unique original identities, retains all original dependency edges and adds required donor edges. Missing, ambiguous, external donor or nonshader dependencies fail closed. The output receipt proves object payload preservation and normalized metadata preservation after reread. Every reachable dependency still needs platform coverage if actually consumed; retained dependency identity is not Metal support.

Apply all qualified containers together to a disposable installation, keeping per-file original hashes/backups. Never install a subset after a failed graft. Texture streaming files are unchanged. Restore all files, the backend settings container and the research helper independently.

The optional `--continuum-backend-menu-presentation=ABS_MANIFEST` consumer waits for menu objects/text and a short stable presentation interval, captures the actual full window at end-of-frame, and writes a structural observation plus PNG. The normal qualification benchmark must return early when `BackendMenuPresentation.Requested`; otherwise it can quit before capture. `--continuum-backend-menu-reference` uses the same consumer on OpenGL with unchanged original-file identities. A structural capture requires a separate inspected visual qualification of text, controls and background. No startup or FPS improvement is implied.
