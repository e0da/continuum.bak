# Captured multiscale workbench

This opt-in consumer loads a `continuum-multiscale-scene/v1` produced from an actual vessel and its actual scaled celestial-body mesh. It does not substitute procedural planet/craft geometry. Body texture bytes, sampler metadata, source transform and the unchanged resident vessel subfixture are digest-bound. The body shader is an explicitly approximate diffuse recipe, not stock atmospheric appearance.

The resident v2 geometry wire omits vertex colors: its producer admits only absent or exactly white source colors. The consumer therefore uploads explicit RGBA white vertex colors once, preserving that semantic for shaders that multiply albedo by `COLOR`. It does not rely on a backend's value for a missing vertex attribute. Nonwhite source colors require a richer admitted representation rather than this normalization.

Copy the canonical `ResidentMaterialFormat.cs` and `MultiscaleSceneFormat.cs` from Core into the private project's `Assets`, along with this tool's updated workbench/runtime/editor files and `ContinuumMultiscale` shaders. Build with the existing `BuildAeroFieldWorkbench.Build` method, declaring `CONTINUUM_MULTISCALE_WORKBENCH_BUILD=1`, `CONTINUUM_SHADER_GRAPHICS_API=Metal,OpenGLCore`, and `CONTINUUM_AERO_WORKBENCH_PLAYER=<new absolute .app>`. The build serializes references to the three original presentation shaders and both diagnostic shaders, and binds the actual player assembly and both copied Core files.

Launch that player with `-force-metal` and:

- `CONTINUUM_MULTISCALE_SCENE=<absolute captured scene manifest>`
- `CONTINUUM_MULTISCALE_OUTPUT=<new absolute output directory>`
- `CONTINUUM_RESIDENT_PART_BUNDLE=<qualified matching part shader bundle>`
- Optional `CONTINUUM_RESIDENT_ORIGINAL_BUNDLE=<original shader oracle bundle>`

The aero workbench bootstrap declines this explicit scene mode. No field bundle or automatic smoke exit is needed. The independent consumer uses an ephemeral loopback port recorded in `multiscale-status.json`, with the established newline-delimited bounded workbench control pattern:

```
status
zoom 2
orbit 25 10
focus OBJECT_ID
preset high
override OBJECT_ID 0.5 1 2
captureframe
quit
materialmode reference|instanced
view composed|craft-color|body-color|craft-depth|body-depth
view craft-flat|craft-world-normals|craft-view-normals|craft-albedo|craft-vertex-colors|craft-uv|craft-material-id
view body-flat|body-world-normals|body-view-normals|body-albedo|body-uv|body-material-id
view craft-linear-depth|craft-log-depth|body-linear-depth|body-log-depth
focusinstance CAPTURED_INSTANCE_ID
debugshaderreload ABSOLUTE_NEW_DIAGNOSTIC_BUNDLE
fixturehotreload ABSOLUTE_SCENE_MANIFEST
snapshotreload ABSOLUTE_NEWER_SNAPSHOT
```

Zoom is log10 metres; asset override arguments are world scale, mip bias and requested geometry error in final display pixels. UI also provides continuous logarithmic distance and three presets. The scene manifest is watched once per second. Candidate preparation/activation precedes retirement; rejected scene/snapshot generations retain the previous resident owner. Hot reload preserves logical object identities, focus, camera distance and policy. Controls freeze during end-of-frame capture and wait for the splash screen to finish. Status binds scene/geometry/texture/shader inputs, actual backend/assembly, effective world/shadow policy provenance, camera anchors, clip ranges, dimensions, submission counters, PNG digest and cleanup scope.

The craft constructor removes its original float root translation **before** combining root orientation with local part matrices. Each frame subtracts authored camera and object anchors in doubles before publishing GPU float translations. The body mesh's authored affine offset is similarly combined before conversion. Craft and body cameras share orientation/FOV/aspect but have separate bounded near/far planes and separate world-scale targets. Original positive linear-depth copies are compared during composition. IMGUI follows at native display resolution.

First admission is opaque-only: translucent vessel states and body/craft layer collisions reject. Directional shadow maps are disabled; shadow policy requests and geometry-error requests are reported unsatisfied. No geometric hierarchy, skinning, detailed terrain, impostor, solar-system content, atmosphere/ocean or temporal history exists here. Selective supersampling/crop is explicitly rejected pending a qualified coverage compositor. Different target resolutions retain only one nearest opaque depth per pixel; cross-domain silhouette coverage is a remaining fidelity gate.

Source/portable checks do not qualify GPU execution. The root-owned native observation must show the actual craft and actual body at two resolving camera ranges, correct orientation/relative placement and occlusion, plus sharp native UI at a changed world scale. Inspect the recorded native images and depth conventions on each backend. This workbench is not a KSP FPS comparison or an arm-to-solar-system completion claim.

The fixture is an admitted material-family subset, not whole-craft coverage. Native status records its family and instance/mesh/texture counts. Geometry diagnostics deliberately use one unlit DrawMesh per actual instance, with the same immutable mesh and current camera-relative affine transform. These views isolate geometry and texture inputs without relying on the normal part shader or instancing variants. MainTex uses the captured texture and scale/offset; material-ID hue is stable by ordered captured material index. Craft COLOR is the admitted explicit-white semantic; body COLOR was not captured and its vertex-color view rejects rather than fabricates values. Normal views encode normalized world/view components from [-1,1] to [0,1]; zero normals encode neutral gray. UV displays fractional raw UV in RG. Readable depth uses the current clip near/far or log(1+metres)/log(1+far), with zero reserved for unwritten pixels. Raw depth remains available and clamps at display conversion.

The built-in `Continuum/MultiscaleDiagnostic` shader is retained by the player builder. A matching shader bundle can replace only cached debug materials with `debugshaderreload`; exact supported shader identity and MainTex/Mode/MaterialColor interface are required. Preparation and hashing finish before the frame-boundary swap; rejected bundles preserve the prior shader/materials. Geometry, captured textures, pose state, camera and socket remain resident. Status binds bundle SHA and reload generation. Returning to composed/color/depth views disables debug geometry without modifying normal materials or global shader inputs. Native appearance, HMR recovery and cleanup remain qualification gates; these diagnostics carry no fidelity or performance claim.

Single-level body captures report `unsupported-single-level` for mip policy: assigning a mip bias cannot select absent coarser levels. Multi-level bias application also remains visually unqualified until inspected.

Scene-v2 whole-craft diagnostic consumer

An optional content-bound `wholeCraft`/`wholeCraftSha256` scene input selects `WholeCraftRuntime` as the sole craft draw, bounds, anchor and focus owner. It reads the bounded WCG1 geometry contract: actual positions, available normals/UV/tangents/colors, and exact triangle submeshes. One ordinary DrawMesh is issued for each captured enabled/active draw slot. The former mapped fixture remains only a captured lighting/global/camera lease donor; it never draws beside the whole consumer. This preserves existing mapped-only fixtures and makes the temporary donor dependency explicit in status.

Default whole appearance is deliberately approximate, opaque and two-sided: selected captured MainTex and scale/offset, an exposed Color/BurnColor tint, and actual vertex RGB. Missing MainTex defaults white, absent colors default white, missing normal/UV channels remain zero; each fallback is counted. All diagnostic normals/albedo/UV/material-ID/depth views operate the selected whole geometry. Original shader names, keywords, property tables, renderer identities/flags, frozen-skin facts, texture capture modes and omission reasons remain in the immutable source manifest. Source forceRenderingOff is retained and respected alongside enabled/active state; suppressed rows remain in the coverage ledger but do not contribute draws, visible bounds or layers. Unknown culling uses two-sided diagnostic geometry; transparency, normal maps, specular and material property blocks are not reproduced or qualified. Nontriangle/unavailable geometry is recorded by the producer's omission ledger.

`focusinstance` selects the stable draw ID. Whole geometry and poses are an immutable generation; subset `materialmode` and `snapshotreload` commands reject while whole is selected. Reload the bound scene generation to change whole assets or poses. Debug shader hot reload prepares both whole and donor cached diagnostic materials plus the body material before swapping the shader lease, so it does not reload geometry/textures or lose active resident assets. A debug bundle now requires `_MainTex`, `_Mode`, `_MaterialColor`, `_Tint` and `_Cull`. Whole mode7 is the approximate albedo consumer; modes0–6 retain flat/normals/raw-albedo/colors/UV/material-ID diagnostics. The player build receipt additionally binds WholeCraftRuntime and the canonical copied WholeCraftSceneFormat source. Root-owned native evidence must still establish actual whole geometry/coverage, views, HMR recovery and owned shutdown; table counts are not those proofs.

Whole-craft packet owner

`materialmode reference|grouped` selects ordinary per-source draws or cached instanced packets for the same whole diagnostic recipe. Legacy mapped fixtures retain reference|instanced. Packet keys contain exact mesh/submesh/layer and a canonical consumed binding: the same captured texture-table object (full native descriptor/sampler), exact MainTex scale/offset bits, and the selected Color-or-BurnColor tint in original captured property order. Original material IDs and facts remain immutable aliases; material-ID hue is supplied per source in both paths. Meshes are not merged by name/content or simplified. Source visibility, colors, affine matrices and focus identities remain identical. Packets contain at most 1023 sources; the actual slicing helper was checked once with 1024 sources and returned 1023,1.

The shader explicitly uses instancing object matrices and per-instance material identity in the visible pass and an original instancing ShadowCaster pass. The player builder retains four variants (Normal reference/INSTANCING_ON, ShadowCaster SHADOWS_DEPTH reference/INSTANCING_ON), reads back pinned KeepAll stripping and restores prior settings. Shader HMR now requires `_ContinuumPacketContract=1` in addition to the texture/mode/tint/cull/identity interface; this declared capability rejects the prior nonpacket diagnostic bundle, but does not substitute for native image parity. HMR prepares both reference and canonical packet materials before swapping; membership/matrices/MPBs and immutable assets remain resident.

Both modes share unchanged-anchor and unchanged-mip-bias fast paths. Native status records canonical recipes, packet count, actual last submission calls, cumulative submission ticks and separately charged cold preparation ticks. Submission ticks are only the managed DrawMesh/DrawMeshInstanced enqueue envelope; complete-frame timing includes anchor/bounds/packet updates, body draw, depth generation/copy, composition, native UI and waits.

`benchmark 2 10` starts a bounded warmup and monotonic capture (warmup0..30, capture1..30 seconds), independent of simulation time. It reuses the existing workbench Update-boundary protocol: one witnessed previous presentation, consecutive frames, no initial partial interval, final deadline straddler omitted, capacity65536. Raw frame start/end ticks and submission intervals/calls are exported to a separate nonce-time file. Controls, scene polling, capture and HMR freeze; GUI/scroll mutations and periodic status writes stop. Socket commands during retained capture invalidate completion. `cancelbenchmark` or quit records interruption; controls or presentation drift, render failure, capacity overflow and source manifest/bundle drift invalidate. VSync and frame cap restore on all owned completions/cleanup. These inclusive wall intervals are not GPU durations and provide no gameplay/FPS promise. Native exact decoded-color/normal/material-ID/depth parity and full-window comparisons remain the actual acceptance gates.
# Whole-craft packet experiment result

The first native experiment observed 656 ordinary submissions versus 109 packets across 47 consumed recipes. Normals, material IDs, UV and linear-depth pixels matched exactly; textured sampling had a sparse reproducible difference. Two short observations per mode showed roughly 7% lower mean frame cost, 38% more whole-process CPU and worse tail latency. Reference remains the default. The grouped alternative has not passed its frozen exact-image gate or resource promotion criteria; no game performance or stock material equivalence follows from it.

Process CPU/RSS is separately timestamped around the retained frame window and includes its final straddler. Submission timing is a nested enqueue envelope; cold preparation is charged separately. Inspect the raw native evidence before drawing conclusions about pipeline ownership. Persistent GPU state is a next alternative, not a measured explanation for the current CPU regression.

Retained transform and combined depth owner

`WholeCraftRuntime.SetRenderMode` additionally accepts `retained-scalar` and `retained-grouped`. Both execute the same instancing shader and the same packet-ordered source table. Scalar records one count1 command per visible source; grouped records one command per packet. This is a separate treatment from legacy reference/grouped, whose textured native parity remained unresolved; no prior RED is converted into a pass.

One cold, linear RGBAFloat point/clamp texture contains eight texels per visible source: four complete root-relative affine rows, three inverse-transpose normal rows, and the original material alias hue. Admission rejects singular/nonfinite inverses, unsupported float textures, or a row count above the actual native texture limit. The table has no mip levels and uploads once. Mirrored/nonuniform transforms retain their actual affine and normal matrices; diagnostic culling remains two-sided. Anchor changes update material uniforms while geometry and source state stay resident. Scalar and grouped use identical arithmetic and source order within each packet; no exact-image claim precedes the frozen native comparison.

The host calls `ConfigureRetainedTargets(color, positiveDepth)` after target creation and `Submit(camera)` directly after configuring the craft view. It skips craft Camera.Render and its automatic depth/copy while retained, restoring them for legacy modes. Color must have a depth attachment and both targets must be matching, single-sample, native-created targets; positiveDepth is RFloat and native MRT capacity must be at least two. An explicitly executed pass0 command buffer owns viewport, MRT clear and color plus positive linear eye-depth, sharing the color target's hardware depth. GPU projection is computed with renderIntoTexture=true; exposed vector-row properties receive actual view and view-projection matrices, cached until changed. No Unity global matrices or camera events provide the retained view. RenderTexture.active restores in finally. The owner draws all admitted visible rows without per-row frustum culling and has no shadow consumer. Body rendering and composition remain separate host responsibilities. Prior Before/AfterForwardOpaque attachment probes retained correct separate depth but black color; both remain failed native evidence, not a claimed event-order fix.

Commands and materials prepare before old leases are released; scene disposal releases commands before state texture/materials. HMR requires `_ContinuumRetainedContract=2`, `_ContinuumExplicitViewContract=1` and the eight actual matrix-row properties; it rebuilds command references against staged materials without reloading geometry/textures/state. `StateUploadCount/Bytes`, `StateTextureId`, `CommandBuildCount`, `RetainedCommandCount`, `NativeExecuteCount` and `ViewUniformUpdateCount` expose actual ownership work. `LastSubmissionCalls` in retained modes counts recorded native commands, and submission ticks measure only managed view/control and ExecuteCommandBuffer enqueue; native execution is included in the complete-frame window. Shader support, MRT depth/UV correctness, exact scalar/grouped pixels, recovery, and full-workload cost remain native gates.

Multi-owner HMR calls `StageDebugShaderCommit(Material[])` before changing any owner, then commits that `DebugShaderCommit` lease first. Preparation records commands once; commit does not repeat it. Disposing an uncommitted lease releases only its commands: the caller still owns rejected staged material destruction. Successful commit transfers the material table to the runtime. Legacy Material[] commit wraps this same API.

The native explicit-owner experiment rendered occupied color and positive depth after both camera-event versions had produced black color. Scalar/grouped normals, material IDs, UVs and displayed linear depth matched exactly in the frozen image region. Textured composition differed at 45 pixels, unchanged after shader/scene reload; its exact gate remains failed. The legacy-reference comparison differed at 3142 pixels and does not establish reference fidelity. Cause remains unresolved. No repeated unchanged color experiments are required before choosing a different resolving action.

One 83,968-byte state upload served 656 visible sources. Camera orbit and planet focus changed view uniforms without another state upload or command generation; target resize rebuilt commands while retaining state. Native shader HMR changed gray to cyan with the same geometry, textures, camera, socket and state texture. A previous shader contract and invalid pose rejected; valid scene reload replaced the resident generation while retaining mode/shader. Owned quit restored settings and removed hooks.

Two composed observations per mode, in reference/retained-grouped/retained-grouped/reference order, gave neutral mean frame cost (paired changes -1.27% and +0.60%), lower process CPU per resource-window frame (-9.12% and -5.18%), and worse p99 (+11.25% and +19.60%). Upload/command counters stayed constant throughout each capture. Resource CPU is inclusive whole-process work in its separately timestamped window, not GPU time or exclusive renderer cost. These are diagnostic cost observations with failed color fidelity, not a gameplay gain or promotion result. Reference remains the default. Stop unchanged timing repetitions and move to the next measured owner.
